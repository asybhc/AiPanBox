# BaiduVault 多网盘接入指引（13 库）

> 版本：基于 OpenList v4.2.9 运行实例实测（`/api/admin/driver/list`、`/api/admin/driver/info`）+ OpenList 官方仓库源码核对（drivers/*/driver.go）。
> 证据标注约定：【API 实测】=本次从运行实例接口取到；【源码实测】=本次逐文件核对过实现；【文档/社区】=OpenList 官方文档或社区共识，**未实测**；【项目实测】=本项目此前验证过。
> 本文只做只读调研与方案，不含任何真实账号凭证。

## 0. 结论

- 13 个网盘**全部有对应驱动**（无一落空），且 13 个驱动**全部实现 server-side Move**（源码实测），全部可叠加 chunker 512M 分片。
- 稳定可长期无人值守的 4 个：**阿里云盘(Open)、123(Open)、115(Open)、百度**（均 refresh_token/OAuth，OpenList 自动续期）。
- 需手工获取一次 token、之后较稳的 3 个：**联通 WoPan、UCTV、QuarkTV**。
- 需要定期维护的 6 个：**夸克、UC、115 Cloud、天翼、移动、迅雷**（cookie/验证码/风控类）+ **蓝奏/蓝奏优享/光鸭**按档归入中或折腾，详见矩阵。
- **建议接入顺序：阿里云盘 Open → 123 Open → 115 Open → 联通 → 其余按需。**

## 2. 每库接入卡

> 「凭证获取」中未实测的步骤均标【文档/社区】；本项目实际走过的只有百度。

### 2.1 阿里云盘 → AliyundriveOpen【稳】
- **授权**：官方开放平台 OAuth，refresh_token。
- **凭证获取**：用 OpenList 文档页提供的刷新令牌工具扫码（阿里云盘 App 扫码授权后返回 refresh_token）【文档/社区】；有开发资质可自建 client_id/secret（open.alipan.com）【文档/社区】。
- **过期/续期**：OpenList 自动用 refresh_token 换 access_token，长期免维护；refresh_token 本身在每次使用后轮换，由驱动自动回写【文档/社区】。
- **人工验证码**：不需要。
- **已知限制**：官方对第三方 Open API 有流量/权益包政策，超限限速【文档/社区，未实测】。
- **Move**：✅ 源码实测 → chunker 可开。

### 2.2 115 → 115 Open【稳】
- **授权**：115 开放平台 OAuth，access_token + refresh_token（均必填）。
- **凭证获取**：115 开放平台（open.115.com）申请应用，走 OAuth 授权码流程拿双 token【文档/社区】。
- **过期/续期**：refresh_token 自动续【文档/社区】。
- **已知限制**：limit_rate 字段存在（API 实测），具体配额【未实测】。
- **Move**：✅（115_open、115 均源码实测）→ chunker 可开。
- 备选 `115 Cloud`：cookie 或扫码（qrcode_token），cookie 掉线需重新抓【折腾档】。

### 2.3 123 → 123 Open【稳】
- **授权**：123 云盘开放平台 OAuth（ClientID/ClientSecret/AccessToken/RefreshToken 全必填）。
- **凭证获取**：123pan 开放平台申请开发者应用，OAuth 授权【文档/社区】。
- **过期/续期**：RefreshToken 自动续【文档/社区】。
- **已知限制**：上传有并发/频率限制；DirectLink 直链功能可选（字段实测）【文档/社区，未实测】。
- **Move**：✅ 源码实测 → chunker 可开。

### 2.4 夸克 → Quark（cookie）/ QuarkOpen【折腾 / 中】
- **cookie 版（Quark）**：浏览器登录 pan.quark.cn → DevTools 复制整段 Cookie 填入【文档/社区】。掉线表现：列目录报错/空；续期=重新抓 cookie。风控较敏感，频繁操作易触发滑块【文档/社区，未实测】。
- **QuarkOpen**：需 app_id + sign_key + access/refresh token（夸克开放平台资质，个人难申请）【文档/社区】。
- **QuarkTV**：TV 端 refresh_token + query_token（抓包获取），TV token 存活期较长【文档/社区，未实测】。
- **Move**：✅（quark_uc、quark_open 均源码实测）→ chunker 可开。

### 2.5 百度 → BaiduNetdisk【稳，已接入】
- **授权**：开发者应用 AppKey/SecretKey + 授权码模式 refresh_token（只能用一次，务必保存）。
- **凭证获取**：pan.baidu.com/union/console/applist 建「软件应用」（回调 oob）→ 浏览器走授权码 URL → code 换 token（scope basic,netdisk）【项目实测】。
- **过期/续期**：OpenList 自动续【项目实测】。
- **已知限制**：第三方接口上传限速约 4.65MB/s【项目实测】；加密文件名 119 字符上限【项目实测】。
- **Move**：✅ 源码实测 → chunker 已开（512M）。

### 2.6 天翼云盘 → 189CloudPC【折腾】
- **授权**：账号密码 + 图形验证码（validate_code）/ 短信验证码（sms_code）登录后拿 token。
- **凭证获取**：直接填账密，OpenList 登录时可能弹验证码要求人工完成【字段实测】。
- **过期/续期**：驱动持 access_token+refresh_token 自动续【字段实测】，但触发风控需重新过验证码【文档/社区，未实测】。
- **已知限制**：家庭云/个人云区分（type/family_id 字段）；上传方式可选（upload_method）【字段实测】。
- **Move**：✅（189pc、189 均源码实测）→ chunker 可开。

### 2.7 移动云盘 → 139Yun【折腾】
- **授权**：authorization（抓包）或账号密码+短信验证码。
- **凭证获取**：填账密走短信验证，或从 App/网页抓 authorization【字段实测】。
- **已知限制**：type/cloud_id 区分个人/家庭云【字段实测】；限速【未实测】。
- **Move**：✅ 源码实测（139）→ chunker 可开。

### 2.8 UC 网盘 → UC（cookie）/ UCTV【折腾 / 中】
- **UC**：与夸克同源（quark_uc 实现），浏览器登录 drive.uc.cn 抓 cookie【文档/社区】。
- **UCTV**：TV 端 refresh_token + query_token + link_method，token 更长寿【文档/社区，未实测】。
- **Move**：✅ 源码实测 → chunker 可开。

### 2.9 蓝奏 → Lanzou【折腾】
- **授权**：账号密码 或 cookie；type 字段区分账户/分享链接模式【字段实测】。
- **已知限制**：免费账户**单文件上传上限约 100MB**【文档/社区，未实测】——**512M 分片会超限，必须把 chunk_size 调小到 ≤90M，或该库不开 chunker**。
- **Move**：✅ 源码实测；**Copy 未见实现**（不影响 chunker，只影响库内复制）。
- **Move**：✅ → chunker 可开但须调小分片。

### 2.10 蓝奏优享 → ILanZou【中】
- **授权**：**username + password + ip 全必填**（ip 疑似登录环境绑定/验证参数，具体语义【未实测】）。
- **已知限制**：优享版单文件上限高于免费版【文档/社区，未实测】，分片建议仍 ≤200M 保守起步【未实测】。
- **Move/Copy/Rename**：✅ 全部源码实测 → chunker 可开。

### 2.11 光鸭 → GuangYaPan【中偏折腾】
- **授权**：client_id 必填 + 手机短信流程（send_code → verify_code/verification_id）→ access/refresh token + device_id/device_sign【字段实测】。
- **凭证获取**：OpenList 添加页内发起短信验证，人工收码完成登录【字段实测】。
- **过期/续期**：refresh_token 字段存在，可自动续【字段实测】；掉线需重新短信验证。
- **Move**：✅ 源码实测 → chunker 可开。

### 2.12 联通 → WoPan【中】
- **授权**：refresh_token（+access_token, family_id 家庭云）。
- **凭证获取**：联通云盘 App/网页抓包拿 refresh_token【文档/社区，未实测】。
- **过期/续期**：refresh_token 自动续【文档/社区】。
- **Move**：✅ 源码实测 → chunker 可开。

### 2.13 迅雷 → ThunderX【折腾】
- **授权**：username + password，登录可能要求 **captcha_token（人工过验证码）**【字段实测】。
- **凭证获取**：直接账密；触发验证码时在 OpenList 页面人工完成【文档/社区】。
- **变体选择**：个人云盘用 `ThunderX`；`ThunderBrowser` 多了 safe_password（安全密码）用于浏览器版；**Expert 三个变体要求 algorithms/captcha_sign/timestamp/client_secret 等抓包参数，不建议碰**。
- **已知限制**：use_video_url 字段存在（直出视频地址）【字段实测】；限速/风控【未实测】。
- **Move**：✅（thunderx、thunder、thunder_browser 均源码实测）→ chunker 可开。

## 4. 多库落地方案（combine 聚合，单端口 8088）

### 4.1 命名与路径前缀（建议）

| 前缀 | 库 | 前缀 | 库 |
|---|---|---|---|
| `/baidu` | 百度（已有） | `/uc` | UC |
| `/ali` | 阿里云盘 | `/lanzou` | 蓝奏 |
| `/115` | 115 | `/ilanzou` | 蓝奏优享 |
| `/123` | 123 | `/guangya` | 光鸭 |
| `/quark` | 夸克 | `/wopan` | 联通 |
| `/189` | 天翼 | `/thunder` | 迅雷 |
| `/139` | 移动 | | |

OpenList 侧：每库添加一个存储，挂载路径与上表一致。rclone 侧仍只有一个 `[opl]` webdav remote。

### 4.2 rclone.conf 多库形态（示意）

```ini
[opl]
type = webdav
url = http://127.0.0.1:5244/dav
vendor = other
user = <OPENLIST 用户>
pass = <obscured>

# 每库一对 crypt+chunker（密钥各自独立）
[baidu_crypt]
type = crypt
remote = opl:/baidu/secret_vault
password = <K1>
password2 = <K2>
[baidu_chunk]
type = chunker
remote = baidu_crypt:
chunk_size = 512M
name_format = *.rcc##

[ali_crypt]
type = crypt
remote = opl:/ali/secret_vault
password = <K3>
password2 = <K4>
[ali_chunk]
type = chunker
remote = ali_crypt:
chunk_size = 512M
name_format = *.rcc##

# …其余库同构；lanzou 特例：
[lanzou_chunk]
type = chunker
remote = lanzou_crypt:
chunk_size = 90M        # 蓝奏单文件限制，分片调小（未实测，保守取值）
name_format = *.rcc##

[vault]
type = combine
upstreams = baidu=baidu_chunk: ali=ali_chunk: 115=115_chunk: 123=123_chunk: quark=quark_chunk: 189=189_chunk: 139=139_chunk: uc=uc_chunk: lanzou=lanzou_chunk: ilanzou=ilanzou_chunk: guangya=guangya_chunk: wopan=wopan_chunk: thunder=thunder_chunk:
```

- 启动命令从 `serve webdav baidu_chunk512:` 改为 `serve webdav vault:`，其余参数不变。
- **播放/列表/resume 全部以路径前缀区分库，天然隔离**。
- 跨库 move 不支持（combine 限制），但 chunker 只在库内 move，无影响。

### 4.3 keys 文件分库格式（`keys\rclone-keys.txt`）

```
=== 库: baidu (BaiduNetdisk, /baidu) ===
crypt password : <K1>
crypt password2: <K2>
=== 库: ali (AliyundriveOpen, /ali) ===
crypt password : <K3>
crypt password2: <K4>
...
```

**任何一库的密钥丢失，该库云端密文永久不可解**——分库后更要把整个文件离线备份。

### 4.4 chunker 开启判定表

| 库 | Move（源码实测） | chunker | 分片建议 |
|---|---|---|---|
| 百度 / 阿里 / 115 / 123 / 夸克 / 天翼 / 移动 / UC / 联通 / 迅雷 / 光鸭 / 蓝奏优享 | ✅ 全部 | ✅ 开 | 512M（沿用现值） |
| 蓝奏 Lanzou | ✅（无 Copy） | ⚠️ 开但调小 | ≤90M（免费单文件限制【文档/社区，未实测】） |

> 若未来某库被证实 Move 不可用：退回「只 crypt 不分片」——该库大文件播放时 rclone vfs 需缓存整个文件、首次拖动缓冲显著变长、受网盘单文件上限约束；UI 库卡片应显示「不分片」徽标并在首次播放大文件时提示。

## 5. 应用侧配合机制

### 5.1 凭证失效检测（三层）

1. **定时探测**：应用每 5–10 分钟对每库根路径做一次轻量 `PROPFIND /dav/<前缀>/`（深度 0）。连续 2 次失败 → 标记「凭证过期」。
2. **OpenList 侧状态**：`GET /api/admin/storage/list` 每存储有 `status` 字段（work / 错误信息）【API 实测接口存在】，掉线驱动会带错误文本（如 cookie 失效），可直接读取归因。
3. **播放/列目录失败冒泡**：播放或列表请求失败时，再对该库做一次 PROPFIND 复核——能区分「这个文件的问题」还是「整库掉线」。

### 5.2 UI 三态（库卡片徽标）

- 🟢 **库正常**：探测通过、storage status=work。
- 🟠 **凭证过期**：storage status 报错含 token/cookie/授权类关键字，或 PROPFIND 401/403 → 按钮「重新授权」跳转 OpenList 管理页对应存储编辑页（`http://127.0.0.1:5244/@manage/storages`）。
- 🔴 **服务异常**：openlist(5244)/rclone(8088) 进程或端口失联（ServiceManager 健康检查发现）→ 按钮「重启服务」，与凭证问题明确分开，避免误导用户去重登。

### 5.3 掉线恢复 SOP（应用内置文案）

cookie 类库掉线 → 提示语：「XX 网盘凭证已过期（cookie 平均存活 X 天-数周，属该网盘风控行为）→ 点我打开重新登录指引」→ 引导至对应「接入卡」步骤。
